# Data and storage

Running SOP manages local work data separately from the shared folder chosen by the user. Local records and recording remain available without shared-folder authorization. The current interface does not provide backup export.

## Local data

The Chrome extension uses `chrome.storage.local` for local settings, drafts, recordings, notes, local view counts, and records awaiting sync. Categories are stored separately from SOP content in `categories.json` at the root of the selected shared folder, rather than in extension-local storage. Workflow matching mainly uses URLs; it does not read page body text or form values.

Recording uses clicked control text or `aria-label`, associated label text, active dialog/tab titles, page titles, and redacted URLs. It does not collect input field values. Manually entered work addresses and notes may also identify business information. User-triggered screenshots may capture anything visible on the page. Review content before saving or sharing it.

Before clearing extension data or uninstalling, publish and verify anything you need to retain. Keep backups of shared files in a location that meets your organization's requirements.

## Optional shared folder

The user selects a shared folder through Chrome's folder picker. A fresh installation has no default folder, and the extension does not read or write shared data until a folder is selected. Chrome's file system access permissions control the authorization scope. Read and write permissions are checked separately; operations stop and show a message if authorization is missing.

Shared content may include:

- Published workflows and their catalog index.
- Category metadata separate from workflow content, such as `categories.json`.
- Content explicitly published by the user, ratings, or anonymous device statistics files.
- Display files generated by the dashboard tool at a user-specified location.

Publishing is explicitly triggered by the user. If automatic catalog checks were enabled, the extension reads the catalog every minute while the browser is running. After a statistics folder is connected and sync is enabled, view counts and ratings are written automatically. Disabling automatic catalog checks or statistics sync stops subsequent background activity but does not delete previously shared data. The current settings no longer expose these switches; upgrades retain configurations explicitly enabled in earlier versions. Selecting a folder performs one check without enabling background activity by default.

Settings and the folder SOP overview provide **Category settings** to create or rename categories, choose their parent, icon and color, and delete empty categories. Each published SOP row has **Assign category**, including an Uncategorized choice. These controls require a live, explicitly selected directory and valid category data. Saving requests write permission only from the user action, and edits are shared by users of that folder. Folder filesystem permissions govern access; these controls do not add owner roles. Other overview tabs read the updated categories on refresh.

Saving categories validates the data, backs up existing category metadata, checks for revision conflicts, and reads the written file back for verification. It does not rewrite workflow content. Revision-based optimistic conflict detection across devices is not a cross-device transaction lock.

## Dashboard generation tool

`tools/build-dashboard.cjs` generates a dashboard from a shared folder specified by the operator. Confirm the source and access scope before running it. Generated files may aggregate catalog metadata or statistics and should follow the shared folder's access policy. Data in `examples/storage/` is for testing; it does not represent real users or actual SOPs.

## Example layout

The repository's `examples/storage/` contains synthetic samples suitable for public sharing: a generic demonstration workflow with the work address `https://example.com/work`, empty category data, and synthetic illustrations. It contains no real NAS paths, internal SOPs, user screenshots, or production data.

## Cleanup and retention

Users can delete local drafts through the extension's draft management controls. Uninstalling may cause Chrome to remove extension-local storage. Shared files are managed by the user or their organization; the extension does not clear shared data on its own. Follow your organization's backup, access, and retention policies.

## Folder connections

Click the folder area in settings to select a local folder, or first connect a network computer/NAS share through your operating system and then select that folder. The extension does not automatically discover, sign in to, or mount SMB servers, and it does not obtain a universal path usable across devices.

The picker first requests read permission. It recognizes `catalog.json` in the selected folder or the known subfolders `SOP`, `sop`, and `工作SOP/SOP`. If several libraries are found, it asks you to select one directly rather than choosing for you. An invalid folder, a mismatched folder, or cancellation preserves the previous connection. Settings display the folder name and SOP count; internal identifiers are not presented as user addresses. For an empty folder, the extension requests write permission before creating and verifying an empty `catalog.json`. A corrupt existing catalog is not overwritten.

The earlier **Choose catalog file** connection option accepted only a library's `catalog.json`. Selecting that file alone did not authorize access to adjacent files or activate the new connection. **Choose its folder** completed the connection after comparing native file identities. This was a catalog connection mechanism, not an importer for an individual SOP; these legacy controls are no longer shown in the current settings.

Handles are stored in the extension's own IndexedDB and bound to a local connection identifier. Folder reads do not depend on **Allow access to file URLs**; the legacy `file://` address mode still requires that switch. Automatic checks can run only after the user selects and connects a folder and explicitly enables them. A manual check does not enable background polling. If permission expires or the share is not mounted, the extension asks the user to select it again. Cached content must still pass validation and must not be treated as live data.

Folder connections and publishing use the same authorized folder, with write permission requested separately for publishing. The legacy manual-address mode retains its separate publishing configuration for migration. Selecting the folder-based mode avoids a duplicate publishing picker. Statistics sync remains a separate, explicitly enabled function and does not start automatically when a library is selected.
