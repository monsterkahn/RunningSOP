# 手机二维码与阅读页

## 给使用者

1. 从总表进入“SOP 内容库”，点击“二维码标签”。
2. 填写手机可访问的阅读页面地址，例如 `https://storage.example/sop.html`，点击“保存地址”。示例地址不是已部署服务。该设置只保存在当前浏览器，不会写入 SOP 正文。
3. 点击“下载全部标签”，每份 SOP 生成一个独立二维码；下载的 HTML 用浏览器打开，可打印或另存为 PDF。
4. 也可以先打开一份 SOP，再点击“手机扫码”，下载单个 SVG 或测试打开。
5. 用手机实际试扫确认能阅读，再张贴。手机需在能够访问存储器的网络中；二维码本身不授予访问权限。

## 部署者

`npm run build` 生成 `dist/sop.html`，这是无需扩展的独立手机阅读页。将其部署在工作 SOP 网站根目录，与 `SOP/` 目录相邻：

```text
网站根目录/
  index.html       总表（可选）
  sop.html         手机阅读页
  SOP/
    catalog.json
    workflows/...
```

存储器的挂载路径是电脑文件系统位置，不是手机网站地址。将 HTML 放到共享文件夹并不自动启动 HTTP 服务；需要存储器网站服务将这组目录映射为可访问的 HTTP(S) 地址。不要把存储器管理控制台登录页直接当作阅读地址。

如果站点目录不同，可构建指定相对路径的阅读页：

```sh
node tools/build-mobile-reader.cjs dist/sop.html ./SOP/catalog.json
```

目录必须在阅读页同源且所在目录内部，不能指向外站、上级路径或查询参数。静态服务需要正常返回目录、正文和图片文件，JSON 不能被登录页面替代。原来的网页登录机制由站点处理；阅读器不会保存或自动填写密码，不会绕过权限。

## 批量文件生成

```sh
node tools/generate-qr.cjs examples/storage/catalog.json dist/qr-labels https://storage.example/sop.html
```

输出每个 SOP 的 `<ID>.svg`、打印用 `index.html` 和 `links.json`。仅处理验证过的目录 ID。运行前校验地址并生成整批内容，地址错误不会开始写文件；不会清理已有文件。重新生成到同一文件夹时，已删除 SOP 的旧标签不会自动删除，请勿继续使用旧标签。

## 固定入口和版本

入口格式是 `sop.html?id=<工作流ID>`，不包含正文哈希或版本号。每次打开或手动重新读取时请求当前目录，验证正文与图片后显示版本；阅读过程中不轮换版本。升级 SOP 时保留 ID，移除 ID 后旧二维码显示不存在，不会自动指向别的 SOP。更换网站域名或路径需要保留旧入口转发或重印二维码。

手机页当前提供中文只读展示，包含图片缩略图、带标记的放大图、异常处置、报告点和审批点。它不会记录完成状态、执行审批、发送评价或采集查看次数；不能把打开手机页计为完成或已审批。

## 完整性和网络

编码器本地运行，不调用二维码在线服务。正文和图片使用现有 SHA-256 与结构校验、大小限制、同源路径限制。普通局域网 HTTP 缺少 WebCrypto 时使用本地 SHA-256 实现；HTTP 不提供传输加密，内容哈希也不能替代服务器身份认证。对外发布或传输敏感内容应由部署者配置 HTTPS 和访问权限。

自动测试使用合成内容，已覆盖普通 HTTP、图片标记、最新版读取、未知 ID、正文和图片损坏及错误地址。真实手机相机、网络及存储器网站映射仍需实际试扫验收。
